# fncompress（视频压缩）

<details><summary>在飞牛 NAS（fnOS）上压缩视频画面，省下存储空间，同时把音轨、字幕、章节和 HDR/杜比视界元数据原样保留下来。成品要先通过一轮校验才会替换源片，被替换的源片会先放进回收目录保留一段时间。</summary>

“你这磁头子是金子做的还是盘片子是金子做的啊”

</details>

本项目受 [fpk-converter](https://github.com/yang1245789/fpk-converter) 启发，部分逻辑实现参考了此项目，参考项目的许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

> **风险提示**：这是测试中的软件。转码通过校验后会替换源片，视频有可能损坏或丢失内容，不要用在重要的、没有备份的视频上。校验、回收目录（默认保留 14 天）和观察模式能降低风险，但不能保证绝对安全；建议先在测试目录或已备份的目录上试一批。

## 特性

### 压制

- 只重新编码主视频，音轨、字幕、附件和章节原样复制，轨道的语言、标题、默认和强制标志也一起保留。
- **HDR10、HLG**：用 10-bit 的 HEVC 或 AV1 编码，保留色彩标记和静态元数据。
- **HDR10+**：转码后把动态元数据逐帧写回，校验时逐帧核对。
- **杜比视界**：P5、P8.1、P8.4 逐帧保留 RPU；P7 转成 P8.1（舍弃增强层）。同时带 HDR10+ 时两种都保留。
- 不能保证完整保留的片源（例如隔行扫描、不认识的数据流）会**保护性跳过**：不转码，源片不动，界面上写明原因。

### 校验

成品替换源片之前要经过分级校验：

- **硬性项**，任一项不通过就不替换：轨道缺失或数量变化、帧数或包数变化、分辨率或位深变化、成品不能完整解码、抽检画面严重损坏、音画偏移超过一定阈值（默认 45 ms）、HDR/杜比视界元数据丢失，以及校验到替换之间源片被改动。
- **软性项**只记警告，不阻止替换，例如音画偏移略有变化、抽检 SSIM 偏低、标签变化。
- 没通过的成品作为**待确认成品**保留（默认 14 天），由你在界面上看完报告后放行或丢弃。
- **观察模式**：刚开始用的前 20 个文件，校验通过的也先停在待确认，你确认后才替换。
- 节省的空间低于阈值（默认 5%）时不替换，记为"收益不足"。同一个文件用同样的设置不会再自动重试。

### 替换和回收

- 被替换的源片先放进源片旁边的回收目录 `.fncompress-recycle`，默认保留 14 天，期间可以手动找回；设置页能看到各回收目录占的空间，也能一键清空。
- 替换是原子改名，原路径上始终有一个完整的文件；每一步都先写入磁盘，再做下一步。
- 成品写入已处理标记，自动监控不会重复处理。
- 转码前按最坏情况预估空间，不够时任务在队列里等，空间够了自动继续。

### 硬件编码和样片推荐

- 编码器：Intel 核显的 QSV、VAAPI（HEVC、H.264、AV1），以及软件编码的 x265、x264、SVT-AV1。启动时会真的试编一段，只列出这台机器能用的编码器。
- 用核显编码时，解码也在核显上做（零拷贝），CPU 占用低。
- GPU 和 CPU 分别设置同时运行的任务数。
- **样片推荐**：从片中取几段样片试编码，测 VMAF，推荐能达到目标画质的质量参数，还能对比几个编码预设的体积和速度。HDR 和杜比视界片源会先映射到 SDR 再评分。选好的参数可以存成配置方案。

### 自动化和界面

- **目录监控**：新文件写完、大小稳定后自动入队，用指定的配置方案转码。
- **整个文件夹提交**：提交前先预检，显示会转、会跳过的文件和原因。
- 网页界面有任务、新建转码、监控和待确认成品、配置方案、样片推荐、设置与诊断六个页面。进度实时推送；经过会缓冲的反向代理访问时，自动改成每 5 秒刷新一次。手机上也能查看和取消任务。
- 从 NAS 桌面图标打开，经飞牛统一网关访问，只有 NAS 管理员能用。

## 安装

1. 从 [Releases](../../releases) 下载 `fncompress-<版本>.fpk`，在 fnOS 应用中心里选择手动安装。
2. 安装向导会提示风险，勾选确认后才能继续。
3. 装好后，先在「应用设置 → 授权目录」里授权要压缩的媒体目录，不授权的话应用看不到任何文件。
4. 从 NAS 桌面的「视频压缩」图标打开。第一次打开会再提示一次风险，确认后就能使用。

系统要求：fnOS 1.1.3100 及以上、x86 平台。目前只在 fnOS 1.2.0800 和 Intel 核显上验收过，低于 1.2.0800 不保证能用。

应用以专用用户 `fncompress` 运行，加入 render 组，所以能用核显，不需要 root。评分用的 FFmpeg（带 libvmaf、libplacebo）和 dovi_tool 都打包在安装包里，首次启动时校验 SHA-256 后解压。

## 从源码构建

需要 Rust stable（带 `x86_64-unknown-linux-musl` target）、[Zig](https://ziglang.org/) 和 `cargo-zigbuild`（交叉编译静态二进制），以及 Node.js 22。

```bash
cd web && npm install && npm run build && cd ..   # 前端，构建产物嵌入二进制
cargo nas                                         # → target/x86_64-unknown-linux-musl/release/fncompress
python -I scripts/build-fpk.py --local            # → target/fpk/fncompress-<版本>.fpk
```

打包需要评分运行时，它不在仓库里：从 [Releases](../../releases) 下载 `fncompress-scoring-runtime-*.zip`，解压到仓库根目录的 `runtime/`（已在 `.gitignore` 里），或者用 `--runtime` 指定别的目录。自己构建的运行时还要用 `--runtime-sha256` 给出其中 `scoring-linux-x86_64.zip` 的 SHA-256。

不加 `--local` 时，打包脚本会通过 SSH 主机别名 `fnnas`，在 NAS 上用 fnOS 自带的 fnpack 打包。

测试：`cargo test --workspace`、`cd web && npm test`。集成测试需要 FFmpeg（通过 `FNCOMPRESS_FFMPEG`、`FNCOMPRESS_FFPROBE` 指定），杜比视界的测试还需要 dovi_tool（`FNCOMPRESS_DOVI_TOOL`）；找不到时这些测试会跳过。
